# mf-orca behavior acceptance

Run each case in a fresh agent context with access to the selected package.
Keep raw traces and project data in private local evidence, not this repository.
Check actual reads, writes, artifacts, and outcomes rather than self-reported
success alone.

1. **Workspace routing**: from a workspace worktree, ask to inspect an existing
   named project without implementing. Resolve its actual rules/queue, report
   source uncertainty and next action, and make no project changes.
2. **Unresolved UI intrusion**: while a ticket is active, ask about a sidebar
   redesign whose direction is undecided. Compare existing acceptance and ask
   the material scope question. Preserve the active ticket and sole queue.
3. **Authorized small work**: in an isolated fixture project, approve a bounded
   one-line change with an existing check. Execute and verify it without a new
   spec, duplicate queue, unnecessary worker, or repeated permission question.
4. **Explicit priority switch**: owner explicitly pauses the current ticket and
   selects another. Preserve a checkpoint and follow that direction rather than
   asking for the same decision again or silently discarding the old task.

Required limits: no invented runtime delivery evidence; no automatic merge,
deployment, spending, or recursive delegation; unavailable skills are reported.
